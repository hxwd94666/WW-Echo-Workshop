# 实时评分与收录链路

本文件说明实时评分、自动扫描和手动收录共用的画面识别边界。它不替代评分公式、配装算法或数据合同。

## 1. 四个实时评分场景

### 单件展示页

- 识别右侧详情面板；
- 读取标题、COST、主副词条与右侧词条行；
- 浮层放在词条左侧，不遮挡主副词条；
- 稳定状态只 OCR 右侧详情裁剪区。

### 背包页

- 识别右侧选中声骸详情；
- 左侧网格只用于选格和视觉上下文，不进入稳定评分 OCR；
- 浮层贴右侧词条，显示当前分、理论最高分、档位和贡献；
- 首次/布局变化时读全面板，稳定后读右侧详情。

### 左右对比页

- 左右两侧分别解析；
- 右侧使用当前选中角色模版，左侧参考使用同一模版的独立读取；
- 两侧词条都框选并显示档位；
- 对比页始终读取足够容纳两列词条的全面板区域，不裁成单侧小区域。

### 强化/调谐页

- 词条在左侧，标题/COST 可能跨区域；
- 不做单侧小区域裁剪，使用全面板；
- 页面信息不完整时只显示参考评分，不冒充确定评级，也不自动收录。

## 2. 实时评分的 OCR 区域

实时评分先做布局判断，再按缓存布局选择区域：

- 页面切换、布局未知、距上次全量刷新超过约 2 秒：读全面板；
- 稳定状态的背包/单件展示：读右侧详情裁剪；
- 强化/调谐、左右对比：读全面板；
- 裁剪区域没有主词条：回退全面板重新识别布局。

非宽画布的全面板是有效游戏内容区域；宽画布使用左右面板，避免把中间模型和背景送入 OCR。

实时评分使用快速模式：只做当前评分需要的词条解析，不执行名称/装备者/套装的二次元数据归一，也不写入库存。

- OCR 结果与浮层发布分开。已显示的词条在详情区亮字指纹不变却读出不同内容时保持原样；详情变化后的新值至少经两次一致读取、间隔不少于 0.12 秒才发布。用布局切换或低频全面板刷新做复核，不因模型或背景动画直接替换分数。
- 同一输入重算沿用发布过的分数、评级和档位，更新本帧词条坐标。漏识别短暂保留上一帧，连续缺失约 0.45 秒后撤下旧评分。切换设备、视口、档案、模板或权重时重置；左右对比分别确认。
- 实时 OCR 漏掉 COST 时，在同一帧只补读对应详情标题区域一次，再计算分数。补读仍漏且词条、详情指纹及标题原始像素都一致时，最多沿用 0.45 秒的已确认 COST，仅用于浮层，不记成该帧新读到的 COST。标题变化或超时则降为参考评分；重新读到可信的 COST 后可在同一画面恢复当前评分，冲突值需再确认。按主词条推断的 COST 仍只用于参考评分；收录和强化/调谐页的边界保持不变。
- 对比数值的分隔斜杠统一用中性浅灰，不继承任一侧评级色；一侧没有确认评级时，另一侧仍保留自身评级色。
- 强化策略打开且浮层可见时固定保留标题、策略和期望三行；对比页为左右各预留一组策略和期望。等待结果时两行均显示“计算中…”，完成后才替换建议和期望数据；未配置或失败时显示原因，不显示旧建议。Qt 只为策略区预留高度，宽度和自动定位沿用原有评分浮层规则，超长策略文字单行省略；GDI 沿用原锚点和行数排版。

## 3. 手动收录

手动收录先识别场景，再解析：

- 顶部窄条识别背包、展示、强化页；
- 背包使用右侧详情；展示页先辨认布局，双栏对比确认后仅保留右栏，后续复读和截图沿用同一边界；
- 使用与自动扫描相同的详情回退和记录构建；
- 手动默认取两张新鲜帧，跨度至少 0.3 秒；验证文字区域稳定后，保存最后一帧的原始详情证据；
- 同时只处理一个显式请求；停止或切换档案/捕获源后，已冻结的旧请求也不得入库。冻结后普通失焦不改变手动截图证据；
- 解析成功后才提交；取消、采样变化和档案切换不写入。

## 4. 自动扫描

自动扫描只允许背包页，不额外做顶部场景 OCR；手动收录才需要先区分背包/展示/强化：

- 自动扫描只走前台原生鼠标输入；没有后台许可。原生 SDR WGC/BitBlt 须持有同一宿主窗口及坐标映射。HDR、浏览器和自定义捕获不进入自动扫描，宿主的 PostMessage/Pynput 配置不用于工坊发出扫描输入；
- 点击后须看到目标选中回执及新的两张稳定详情帧。滚轮后用两张新鲜图确认滚动条方向和唯一重叠行，以实测位移更新全局行号；列表变化本身不是回执。歧义、跳页或页面不可见时暂停，不继续发滚轮、不猜位移；
- 等级块和点击位置仅使用当前页测到的卡片，短页不补假槽；重叠区已扫描的位置不会再次输入。暂停或最终排空阶段不会发出输入，恢复、提交前重验档案、捕获、窗口及前台；
- 小区域 packed 读取用于性能；
- packed 字段不完整、布局不确定或有未解决提示时，回退右侧详情；
- 仍无法识别时按不重叠分带重试；
- 只提交冻结快照对应的声骸；
- 回退成功后，packed 阶段已解决的旧警告不会重新加回最终记录。

## 5. 名称、套装与质量

- 名称：内置目录精确匹配、唯一前后缀、0.8 相似度；
- 装备者：角色名称目录匹配；
- 套装：高置信图标匹配时图标优先，文字差异保留在证据中；图标未匹配时套装按缺失/待核对处理，不靠纯文字确认；
- 主词条：第一槽按百分比处理，第二槽固定值；
- 低等级主词条只校验名称、正数和有限值，不套用满级上限；
- 最终提交前清理已解决的旧警告，再交给原生质量服务。
