# 实时评分与收录链路

本文件说明实时评分、自动扫描和手动收录共用的画面识别边界。它不替代评分公式、配装算法或数据合同。

## 1. 四个实时评分场景

### 单件展示页

- 识别右侧详情面板；
- 读取标题、COST、主副词条与右侧词条行；
- 浮层放在词条左侧，不遮挡主副词条；
- 稳定状态只 OCR 右侧详情裁剪区。

### 背包页

- 识别右侧选中声骸详情；
- 左侧网格只用于选格和视觉上下文，不进入稳定评分 OCR；
- 浮层贴右侧词条，显示当前分、理论最高分、档位和贡献；
- 首次/布局变化时读全面板，稳定后读右侧详情。

### 左右对比页

- 左右两侧分别解析；
- 右侧使用当前选中角色模版，左侧参考使用同一模版的独立读取；
- 两侧词条都框选并显示档位；
- 对比页始终读取足够容纳两列词条的全面板区域，不裁成单侧小区域。

### 强化/调谐页

- 词条在左侧，标题/COST 可能跨区域；
- 不做单侧小区域裁剪，使用全面板；
- 页面信息不完整时只显示参考评分，不冒充确定评级，也不自动收录。

## 2. 实时评分的 OCR 区域

实时评分先做布局判断，再按缓存布局选择区域：

- 页面切换、布局未知、距上次全量刷新超过约 2 秒：读全面板；
- 稳定状态的背包/单件展示：读右侧详情裁剪；
- 强化/调谐、左右对比：读全面板；
- 裁剪区域没有主词条：回退全面板重新识别布局。

非宽画布的全面板是有效游戏内容区域；宽画布使用左右面板，避免把中间模型和背景送入 OCR。

实时评分使用快速模式：只做当前评分需要的词条解析，不执行名称/装备者/套装的二次元数据归一，也不写入库存。

## 3. 手动收录

手动收录先识别场景，再解析：

- 顶部窄条识别背包、展示、强化页；
- 背包和展示页只读右侧详情；
- 使用与自动扫描相同的详情回退和记录构建；
- 手动保留冻结帧、三帧稳定性和截图证据；
- 解析成功后才提交；取消、采样变化和档案切换不写入。

## 4. 自动扫描

自动扫描只允许背包页，不额外做顶部场景 OCR；手动收录才需要先区分背包/展示/强化：

- 小区域 packed 读取用于性能；
- packed 字段不完整、布局不确定或有未解决提示时，回退右侧详情；
- 仍无法识别时按不重叠分带重试；
- 只提交冻结快照对应的声骸；
- 回退成功后，packed 阶段已解决的旧警告不会重新加回最终记录。

## 5. 名称、套装与质量

- 名称：内置目录精确匹配、唯一前后缀、0.8 相似度；
- 装备者：角色名称目录匹配；
- 套装：高置信图标匹配时图标优先，文字差异保留在证据中；图标未匹配时套装按缺失/待核对处理，不靠纯文字确认；
- 主词条：第一槽按百分比处理，第二槽固定值；
- 低等级主词条只校验名称、正数和有限值，不套用满级上限；
- 最终提交前清理已解决的旧警告，再交给原生质量服务。

## 6. 验证边界

离屏 Qt、宿主加载、合成画面和原生单元测试不能替代真实游戏验收。真实验收至少覆盖：

- 背包、展示、强化、对比四种画面；
- 手动收录停止后重新开始；
- 自动扫描开始、暂停、继续、停止；
- 长名称、括号名称、短名称；
- 套装图标与文字不一致；
- 低等级主词条；
- 取消、关闭插件和卸载。
