# 界面性能与验证边界

> 本文件记录历史测量方法与样本边界；当前测试数量、引擎版本和功能状态以 [架构](architecture.md) 与 [发布验收](release.md) 为准。

## 优化原则

先用真实 Qt 页面和合成数据测量，再改热点。核心算式、评级表、候选范围、UUID、保护和保存合同不因界面性能优化改变。选择角色不被动计算，已完成的评分投影可以复用，但过期结果仍须显式重新计算。

不降低作业轮询频率来隐藏开销，不关闭取消、过期或写入校验，不把后台首次读取的耗时算成“零成本”。

## 当前缓存边界

| 位置 | 复用与失效 |
| --- | --- |
| 库存模型 | 同行序同UUID按变化行通知；行序或数量变动重置；搜索/排序文本随对应行失效 |
| 库存筛选 | 无搜索不拼接文本；同一次搜索/分类变动只触发一次筛选；保留同组并集和跨组交集 |
| 匹配卡片 | 最多三个角色视图；由结果发布generation、角色要求与所选角色决定，绝不按同UUID猜旧分数 |
| 配装/历史 | 只复用不可变请求和结果的界面摘要；角色、要求、优先级、库存/权重修订和历史来源变化时失效；提交仍走实时校验 |
| 头像 | 解码后的图像有界复用；缓存所属对象、资源修订和字节变化均参与失效；缺图仍保留原请求/重试路径 |
| 卡片栅格 | 最多128项、24MiB像素；首次经过不立即建图，常见项才入缓存；主题、强调色、字号、尺寸、DPI、选中、页脚和头像变化均独立失效 |

栅格只缓存绘制结果，不缓存保护决定或评分计算。显示装备者名字的结果卡片继续跳过装备者头像请求。

`EchoRepository.try_revision()` 每次读取当前修订，不使用过期TTL。通常通过独立只读零等待连接，只执行一个SELECT；本线程已有事务时读取同一事务的未提交修订，此窄路径临时零等待并恢复原busy_timeout。锁忙返回None，真实数据错误传播；退出时在同一互斥锁内关闭两个连接。

## 如何复测

1. 使用临时Config、合成SQLite和合成计划；关闭公网及真实游戏操作，不使用玩家数据。
2. 分别测300、1500、5000件；匹配覆盖1、3、8角色，结果分组覆盖1、3、8、12组。12组是展示压力测试，不等于承诺搜索12角色。
3. 同一平台、字体、缩放、主题下，用独立进程比较旧版和新版；记录冷发布、重复发布、待机、筛选、角色切换、选择及真实视口滚动。大库存样本与小库存样本分别保留，不能只挑最快一次。
4. 用cProfile定位Python开销，另测Qt事件循环心跳和实际重绘；追踪GUI线程SQL时，主连接与修订探测连接都要覆盖。先等待已提交读取完成，再测静止界面。
5. 比对每个UUID×角色的分数、评级和可用原因；检查选择与草稿不丢、固定件不扩大范围、过期结果被拒绝、取消不写入、单角色/全部保存范围不混淆。
6. 改库存、权重、历史来源、头像、主题、DPI和窗口尺寸，检查缓存失效与内存上限。最后从实际安装根重放，断言模块路径没有退回源码。

日志包含精确命令、输入规模、原始输出、退出状态、源码hash和依赖版本；诊断保持有界，不发布私人库存。

## 库存后台查询的当前迁移边界

匹配/配装候选筛选和库存复核筛选/统计已迁入共享 Rust 交互进程。33 个迁移前冻结样例保持相同输出，覆盖确认/待确认、锁/预留、装备者、文本/简繁/拼音、非完整词条、坏时间/无时区/未来时间、微秒半偶舍入和动态时区日历边界。冻结集追踪的 Python 旧筛选/可用性/统计函数调用从 514 次降至 0；文本索引准备和日期格式转换仍在 Python，不计作零 Python 工作。九项新增测试还验证重复位置不合并、显式输入限额、响应身份/行序/统计拒绝、旧请求不发布和健康进程不因业务错误重启。显式计算目录收敛为 228 项通过，相关保存应用契约与包契约各 1 项，Rust 单元 12 项；实际宿主未测。

原生首版的 1500 件无文字查询热 P50 约 34.49 ms，旧 Python 约 5.67 ms；该迁移曾明显退化。分段定位显示约 1 MiB 记录每次重传，JSON 编码和管道/原生接收占主要成本。当前复用显式原生输入快照：命中时请求约 550 字节，Rust 仍按本次筛选条件重新求值，不缓存最终结果，也不按 UUID 猜测记录未变。

Python 与 Rust 各最多保留 2 项、按占用估算累计 8 MiB 的输入身份/快照；父进程不保留完整投影行，只有首次或原生快照失效时重建。身份包含记录实际业务字段、词条值、复核种类、文本索引模式和时间准备模式；时区与当前查询条件仍逐次明确传入。Native 缺失快照只允许在原截止时间内重传一次输入，不切换后端；退出/故障重建后自然失效。原生主循环现转移 JSON payload 所有权，不再深复制完整输入。进程 256/512 MiB 硬限额仍独立生效，缓存估算不是峰值 RSS 验收。

本轮仅测无文字查询这个热点，每种情况 3 次，表中为中位毫秒；不宣称 P95 或全矩阵通过。原生进程先握手，首次一列不含进程冷启动。

| --- | --- | --- |

| 1500 / 同内容输入复用 | 36.69 | 4.02 |
| 1500 / 每次改变输入 | 34.90 | 40.72 |
| 5000 / 首次完整输入 | 未重测 | 137.71 |

当前只跑库存查询与输入缓存两个相关模块的 14 项测试，全部通过；复用此前数值/故障证据，不重跑计算目录、完整性能矩阵或包测试，本轮未重新打包/安装。真实宿主和峰值内存等未覆盖项继续保留。

独立活跃子进程的故障挂起测试中，Reader 关闭触发取消并在 500 ms 断言内返回，计算进程最终回收；测试仓库立即返回，不代表已有阻塞 SQL、线程 join 或真实 OKWW 关闭路径已通过。依赖环境仍缺 ok/numpy/cv2/PySide6，真实宿主心跳、故障存活和 50 次生命周期仍是发布前待完成项。

## Rust 接入的当前验证边界

生产评分/匹配门面已改用 Rust 子进程，保留 UUID×模板顺序和有界缓存。矩阵批次最多 128 件、1024 格；纯显示用的评级说明按阈值缓存，不在 Python 重算评级。Rust 匹配对每件记录只校验一次，完整五副词条不再计算用不到的待解锁潜力项；冻结数值样本仍须逐项通过。

当前同机合成 1500 件×8 角色、关闭结果缓存的五次热运行探索测量：原 Python 门面中位约 156 ms，首版 Rust 通路约 414 ms，分块和重复工作优化后约 345 ms；整矩阵摘要一致。端到端尚未快于原门面，后续继续剖析协议、输入准备和结果模型构造，不把 Rust 核函数速度当作整体收益。

这只是探索测量，不是正式 P95、GUI 心跳或真实 OKWW 验收；本仓库虚拟环境尚未包含 PySide6，本阶段主线程约束用隔离模块桩验证，实际宿主响应仍列为未完成门槛。后续按 Rust 方案执行正式样本量、故障与发布检查，当前迁移包不作为已完成发布。

匹配热路径复测（2026-10-18，同机合成 1500 件×8 角色、关闭结果缓存、每轮更换 UUID、5 次运行）：中位 176.89 ms → 163.54 ms（无缓存分支跳过逐格身份键与缓存探测）→ 158.29 ms（每批预解码标准表，避免逐格重建阈值与提示文案）；最好一次 139.68 ms，最慢 187.28 ms。仍接近旧门面约 156 ms，不宣称已全面超越；本轮只测该入口，未做正式 P95、内存、GUI 心跳，库存查询与持续变化输入未重测。测量脚本与原始输出在 `build/development/follow-up-c-match/`。

同一入口补 50 次样本（关闭缓存、每轮更换 UUID）：P50 174.32 ms、P95 195.80 ms、最小 153.96 ms、最大 208.78 ms；Python 侧 `tracemalloc` 峰值 13.18 MiB（不含 Rust 进程内存）。P95 仍在 500 ms 门槛内；相对旧门面 156 ms 的剩余差距主要来自 JSON 解码、管道读与逐格对象构造，未做 GUI 心跳与真实宿主验收。

offscreen Qt 心跳补充（2026-10-18，1500×8，计算在后台线程、结果在 GUI 线程映射 12000 格）：计算 149–204 ms，结果映射 1.13–1.21 ms；事件循环间隔 P50 5.1–6.0 ms、P95 15.9–17.9 ms、最大 24.25 ms。满足 D 的 P95<100 ms、最大间隔<500 ms，但只证明无同步等待，不等同真实 OKWW/游戏验收。脚本与输出在 `build/development/follow-up-d-gui-heartbeat/`。

源码级生命周期补充（2026-10-18，50 次串行匹配 + 每 10 次一次取消）：同一交互 worker 复用，close 后无存活计算进程，线程数在 0.5 s 内回到基线，单次最大 38.12 ms。未覆盖真实宿主切页、卸载与退出。

真实 OKWW 加载（2026-10-18，`F:/WW/ok-wuthering-waves`，游戏未运行）：宿主识别 `ok_import/echo-workshop` 并加载三个任务入口；`plugin-runtime` 完成（5 个离线资料源、0 warning）；库存复核 193 条完成；主窗口正常显示，无插件异常。只覆盖加载/运行时/库存读取，游戏内收录、匹配、取消、卸载未测。

卸载对照（同日、同机、各 12 个 1 s 样本，游戏未运行）：无插件时宿主 CPU 11.64%、RSS 488.1 MB、81 线程；有插件时 CPU 12.31%、RSS 522.7 MB、88 线程，计算子进程 5.7 MB、0% CPU。空闲增量约 +0.7 个百分点 CPU、+34.6 MB 宿主内存 +5.7 MB 子进程；匹配期间为短时后台负载，未测游戏内 overlay/扫描。

启动/取消专项修复：作业 watchdog 现在覆盖计算阶段，握手也接收取消。使用同一故障测试 Rust EXE、修复前后 Python 调度链的单次对照：握手无输出时，原链路约 3.00 s 后报超时，现链路及时报取消；模拟底层创建迟到 400 ms 时，原链路仍发送 1 次业务请求，现链路发送 0 次；运行中死循环取消的 Future 反馈由约 1.05 s 降至一个 watchdog 轮询量级（本次观测三个场景均在 20 ms 内）。所有测试子进程最终均回收。这里测的是 Future 反馈，不是 GUI 心跳或所有进程已退出的时刻；仅为专项单次对照，不声称正式 P95 达标。

分块协议专项：超过 4 MiB 的 Unicode/引号/反斜杠输入可通过 v2 双向重组，单帧不超过 4 MiB，单逻辑消息最多 64 MiB。10,000 件合成库存、一个冻结匹配模板的请求超过单帧上限，返回 10,000 格与静态冻结样本逐项一致；这验证真实匹配入口不因帧上限裁剪候选，不是同规模性能加速证明。错序、重复、串入其他作业、错误重组身份、截断、超限与传输中取消分别检查；超过总长上限的结果返回有类型错误，不返回截断结果。资源限额仍独立生效，64 MiB 是通信上限，不保证任意高膨胀结构都能在既定进程内存上限内完成。后续继续量化序列化、临时内存与主线程发布成本。

配装差异现按参与角色合并为一次 Rust 请求，只传明确新旧 UUID 的记录，而非整库。六种现行状态已有冻结输出对照；1006 件的合成库存仅投影需要的 6 件。该计数证明通信输入范围收敛，不代表端到端速度或真实宿主响应已通过。

相同八角色/1500 件合成输入、关闭评分缓存、各 50 次热运行的单独探索：可比较差异的中位耗时约从 7.98 ms 降至 4.50 ms；无当前配装时约从 1.25 ms 增至 3.27 ms，两种状态的输出摘要均一致。后者仍有额外通信成本，后续应优先将所需投影随已有配装结果返回；不为掩盖退化恢复 Python 评级后端。这些样本不代替完整性能矩阵或宿主心跳验收。

## 冻结方案重验的迁移边界

`storage/plans.py` 已删除 Python 的单件评分、适配、套装、总分/目标与评级求值，保存、读取、进度及历史摘要由共享 Rust `validate_allocation` 提供证据；schema、冻结身份、哈希与提交修订仍在 Python 校验。归档、档案导入、恢复副本和当前配装入口显式传入同一服务，不通过存储构造第三个引擎。重验在数据库写事务前完成，提交前再检查修订；取消不写入半份方案。

同一五角色/25 件合成冻结计划，保存→读回→标记一个进度→读取列表摘要的前后输出 SHA256 一致；父进程评分、适配、目标、套装与评级函数调用合计由 341 次降为 0。另对单次热验证各取 50 个样本，中位耗时约 3.05→4.01 ms，P95 约 3.69→4.70 ms，计入 Python 准备与通信。该入口尚未端到端快于原实现；后续须减少重复重验与序列化，或复用绑定完整冻结输入的原生证据，不恢复 Python 后端。

这些数据只覆盖该冻结计划，不代表完整性能矩阵、所有历史列表规模或真实 OKWW 响应验收。Qt 主线程等待守卫继续保留；真实窗口、宿主故障与关闭验收仍待执行。

## 已保存方案的单槽替换迁移

候选与预览使用共享交互进程的 `replacement_candidates` / `replace_preview`，Python 不再评分、判约束、算分差/评级或排序。合法性与候选缓存分离：预览由 Rust 重新评估，伪造 `available` 或分数不能绕过保护。只重验目标原五件的物理内容，无关角色变化不阻断；预览传输原五件与选中项最多六条，不再次传整库。正常取消、GUI 等待守卫、历史只读及显式保存边界继续保留。

七种合成状态冻结了评分、分差、理由优先顺序、评级、排序和预览；包含待核对、缺失主词条、过量副词条和负数观测的原有显示。不可用观测仍不可参与替换，其显示求值复用 Rust 逐词条数值内核；正常评分与保存继续严格验证。字节摘要曾发现封顶目标的 `1`/`1.0` 拼写差异，现由 Rust `model_objective` 保留当前冻结模型口径；排序仍使用同一精确比率，不改目标规则，也不在 Python 重建公式。

同机 316 条合成库存、311 个候选，各 50 次热运行：候选端到端中位约 70.62→36.02 ms，P95 约 75.34→41.77 ms；七状态和大池输出摘要均一致，父进程对应业务求值调用由 952 次降至 0。此数据包括准备、通信和结果映射，不包括 GUI 发布，亦不是完整规模/模板/冷热矩阵的发布门槛结论。匹配与冻结重验此前记录的退化仍待独立优化，不据单槽样本宣称全工具加速完成。

## 本轮参考结果

dev8→dev9的Windows/Python3.12/Qt6.11.1、125%合成页面测量：

| 场景 | 旧版 | 新版 |
| --- | ---: | ---: |
| 匹配5000件×8角色，首次结果发布 | 5109ms | 255ms |
| 同结果重复投影 | 2501ms | 0.38ms |
| 同规模切换角色往返 | 4159ms | 76ms |

首次载入大量真实历史计划仍需后台读取和验证冻结资料，取消与数量上限保留。这轮不是求解算法加速，也没有实机游戏扫描或公网慢网性能验收。

## 匹配矩阵性能（2026-10-18 本轮）

同机合成 1500 件 × 8 角色、无结果缓存命中、热进程（同一计算子进程；`ScoreService.compare` 用同一实例连续 6 次，每次更换 `inventory_revision` 使缓存失效，取中位；不含进程冷启动与界面重绘）：

| 实现 | 端到端中位 |
| --- | --- |
| 迁移前 Python 门面（旧记录） | 约 156 ms |
| Rust 首版通路（迁移时记录） | 约 345–414 ms |
| 紧凑对象单元 + 512 件/批 + 8 线程 | P50 约 202.5 ms，P95 约 220.8 ms |
| 列式单元（当前） | **P50 约 179 ms**（40 次热进程，min 167.2）；P95 随系统负载在 193–291 ms 间波动，不作为固定值 |

本轮改动与证据：

1. 匹配单元只下发使用中的字段（`row_scores` 仍由评分/观测入口返回），评级标准按“角色 × COST”去重为批级表，枚举与评级档位改为序号；随后进一步改为列式数组（`ids`/`cells`/`standards`），单格 642→约 96 字节（含逐条贡献）、整批响应 7.72 MB→约 1.25 MB。
2. 批大小 128→512，往返 12→3 次；同批实测 190.9→171.7 ms。
3. Rust 按记录分片并行（上限 8 线程）并保序回收；重复 UUID 与身份校验提前到分片之前，避免分片漏检。
4. 协议兼容性由“语义等价”校验保证：每次重录脚本都把新结构解码回旧结构，逐格比较除被裁字段外完全一致后才写入冻结样例。

仍未达成：距旧门面约 156 ms 仍差约 20 ms（约 12%）；继续的候选是减少 Python 每格 `ComparisonScore`/`Rating` 构造与传输层解码开销。正式 P50/P95、峰值内存、真实宿主事件循环心跳仍未测，不以本表的单一规模中位替代。

## 库存视图查询冷/热路径复测（2026-10-18）

同机 1500 行、无文字与拼音两种查询，均使用同一计算子进程（热进程），各 5 次取中位：

| 路径 | 本轮实测 |
| --- | --- |
| 冷路径（首次或原生快照失效，需重传完整输入） | 约 46.9 ms（无文字）/ 47.8 ms（拼音） |
| 热路径（同内容快照复用，请求约 550 字节） | 约 4.2 ms / 3.3 ms |

冷路径归因（同轮分段）：身份构造约 2.4 ms、投影与文本准备约 3.3 ms、其余约 41 ms 在请求编码、管道传输、原生解析与求值。也就是说冷路径成本来自**跨进程完整载荷**，不是 Python 求值；旧 Python 门面 5.67 ms 的前提是数据已在同进程内存中。

本轮处理：保留该取舍并记录，不为此恢复 Python 后端。若后续仍需压缩冷路径，唯一明确方向是把库存查询载荷改为紧凑/列式编码（影响冻结样例，需单独等价性校验）。热路径已由输入快照复用覆盖，重复筛选不重传。
