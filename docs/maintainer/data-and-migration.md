# 数据身份、兼容与恢复

## 稳定身份

- 产品名 Echo Workshop，Python 包 `echo_workshop`，安装ID `echo-workshop`。
- 宿主任务使用 `EchoWorkshopSettingsTask`、`EchoWorkshopOverlayTask`、`EchoWorkshopScanTask`。
- 数据根为 `config_file.parent/plugin_data/echo-workshop/`，不跟随业务模块位置变化。
- 档案UUID、声骸物理UUID、角色/模版ID、历史计划ID和保护claims不随文件改名变化。
- 匹配与配装分别持久化到 `ComparisonSettingsJSON` / `AllocationSettingsJSON`。

库存 schema4 是唯一支持版本：旧 schema（0–3）不再升级或读取，打开与只读预览都会显式报错，且不迁移、不覆盖原文件。旧版「完整备份／声骸库备份」同样不再导入；只接受当前档案包与当前库存备份。退休游戏锁/弃置字段仍按历史记录无损读取，但不参与评分。

配装偏好可选 `profiles[UUID].search_budget`（`seconds` / `nodes`）。缺失时使用当前默认（10 秒 / 200000 节点），不再回退旧匹配预算；新编辑只写配装偏好，档案导入导出保留该字段。坏预算不阻断独立匹配模式，也不会被自动重置。

界面统一称“模版”，持久化的 `modal_id`、`TemplateModalID`、`角色评分模板` 等既有身份不改名，不迁移用户自定义名称。

当前装备要求必须显式声明 `set_unique_names=true`，按同套装不同名称计件；缺字段、退休计件政策、COST 预算超过 12 或 v1 目标政策均明确报错，不升级、不重写、不删除原文件。匹配要求的可选 `fixed_item_ids` 明确五个槽位的物理 UUID，未指定与显式清空是现行操作中的不同意图，合并要求时保持固定件不变。

当前配装可选 `protected_item_ids` 记录保护子集。缺字段兼容旧 `protected=True` 的全五件；显式空子集代表全部解除，不退回默认五件。保护claims、备份、导入与恢复均按实际子集处理。旧版程序未实现此字段；交付代码回退在玩家数据汇总hash变化时停止，保留现行程序和数据，降级前先导出档案并核对格式兼容性。

## 写入合同

库存SQL事务拥有revision与loadout_revision的检查；计划文件拥有进程/文件锁、提交前校验和原子替换。它们不是一个跨库全局事务，不宣称掉电绝对一致。

取消前未提交部分不算成功；提交后不再追加取消检查将成功伪装成取消。恢复/导入使用暂存、意图和回执；这些底座保留，而不是因删恢复按钮一起删除。

查看历史不回写当前设置。历史分数/评级使用自身快照；修改当前权重不能用新表解释旧方案。当前配装调整保持其他角色与保护关联，替换仅在成功提交时生效。

已保存配装解除保护只接受显式非空UUID集合，同时解除所选项的本地保护和本角色预留；其他声骸与角色保持不变。原“标记装配”入口、应用命令与库存方法已删除；工坊装备者只由设为当前配装统一维护。当前配装写入仍检查库存与配装修订、展示上下文及取消状态，通过同一SQL事务提交；其他角色保护冲突不自动转移。

计划schema1新增可选 `publication={kind,source_plan_id}`，明确 `backup/current/generated` 来源；缺字段为旧版快照，不猜测为手动备份。备份列表仅显示 `backup`；保存版本与旧快照保留在底层证据中，不进入备份列表。`removed_roles=[[character_id,modal_id],...]` 只记录备份列表归档，不更改请求、分数、权重、记录或当前配装引用。逐角色移除持有计划锁，检查完整payload的预览hash与档案归属后原子更新；来源与归档状态随既有档案导入导出保留。另存备份总是新UUID，移除列表重置，仅保留选定角色。旧版程序不理解这些显示语义，降级前先导出备份。

## 未发布版本换名

旧开发插件从宿主扫描目录移出并留作回退，新插件使用新数据目录；不迁移、不删除旧库存或配置。安装不停止正在运行的宿主，需重启后启用新版本。未来发布后的格式升级另行设计迁移合同。

## 关键验证

计算黄金样本比较重构前后字面结果；数据契约验证当前 schema 往返、UUID/本地命名、待核对、冻结计划、进度、保护关联，以及导入取消/冲突无半提交；旧 schema 与旧备份包只验证“显式拒绝且不改动原件”。检查范围与未验证部分记录在发行说明，不用“导入不报错”代替无损证明。
