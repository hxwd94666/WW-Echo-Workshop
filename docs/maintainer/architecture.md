# 架构与模块边界

## 唯一实现

`src/echo_workshop/` 是唯一业务源码。发行时递归打入插件根的 `echo_workshop/`；安装根只放三个薄宿主入口和manifest。没有另一份flat业务源码，也没有构建旧页面再隐藏重排的入口。

| 目录 | 职责 |
| --- | --- |
| core | 共享模型及尚待迁移的纯业务求值；不再包含 Python 配装搜索器 |
| native/compute | 唯一 Rust 计算库及独立进程入口，已接管评分/匹配、配装搜索与预检 |
| application | 显式评分/配装/库存动作、准备作业、取消和日志 |
| storage | SQLite库存、冻结计划、归档、事务意图和兼容恢复 |
| resources | 来源适配、内置快照、校验、缓存与更新 |
| capture | 冻结帧、词条/元数据、视口、遍历状态和网格识别 |
| ui | 库存、匹配、配装、设置及真正复用的组件 |
| adapters/okww | 宿主任务、设备、输入、浮层和生命周期 |

核心层不导入上层或执行IO。应用层不导入页面；页面通过运行时提供的应用服务提交动作，不持有SQLite连接。目录化不是每个类一个文件，规则内聚且单文件最多800行。实时评分/收录的区域、场景和回退见[实时评分与收录链路](capture.md)。

## 计算

迁移中的生产评分/匹配门面 `application/scoring.py` 使用 runtime 持有的 Rust 作业服务，按块提交冻结记录和模板，只映射结果、缓存与诊断，不重复计算评分或适配。快速评分复用此入口。同步门面只供后台调用，检测到 Qt 主线程等待即返回明确错误。

完整匹配结果在同一后台作业内通过 runtime 的 `MatchProjectionService` 提交一次 `match_projection`：Rust 按完整矩阵生成各角色及汇总视图的代表项、全局分数/UUID 顺序、排除和未知统计。同分代表项保持角色原顺序，不改变评分/适配，也不做独占分配。返回投影绑定源记录/分数元组和角色键，身份或矩阵不一致不发布；取消不发布部分投影。卡片只映射索引与状态码，切换角色复用冻结投影，没有同步计算或 Python 排序兜底。旧矩阵模型的排序没有生产调用，现已删除，模型只保持源行与身份索引。开发引擎为 rust-compute-20；新增投影通信的端到端成本尚待相关性能测量，不以原生求值代替真实宿主响应验收。

单件、批量匹配、当前件比较、收录初次观测和左右面板参考评分的生产调用现均使用 Rust；Python scalar/prepared 评分器、档位与词条贡献辅助已删除。`core/scoring.py` 仅保留合同常量和 EchoScoreResult，不导入评级求值，也不保留兼容转发。测试通过仅位于 tests 的原生入口取得数值；生产没有第二套评分后端。页面评级等仍待按 [Rust 方案](rust-compute-plan.md)迁移；库存分类筛选已走 view 模式，排序与真实宿主响应仍待验收。评分保持逐项截断、+25 主词条口径和原精度。

runtime 唯一管理交互/搜索两个有界队列与计算子进程；后台守护队列代替退出时等待的线程池，输入准备超时或取消也能结束任务。准备函数失去协作时停止该队列而非无限新建线程；连续计算进程故障最多重建一次。宿主源码与依赖保持不变，实际宿主响应验收另行执行。

取消与截止时间覆盖启动握手，而非仅在发送业务请求后检查。作业 watchdog 可在底层进程创建仍未返回时先结束 Future，原队列线程继续持有该次启动与回收责任，不另建替代线程；迟到返回的子进程在发送业务请求前重新检查取消、关闭和截止时间并回收。Future 已结束不等于进程已退出，`wait_closed` 只有后台回收完成才确认。握手停滞、启动异常和迟到返回使用真实独立计算进程故障测试；这不替代真实 OKWW 心跳验收。

当前唯一通信协议为 v2，不协商或兼容 v1。`compute_messages.py` 与 Rust `wire.rs` 负责物理帧和逻辑消息：单帧 4 MiB、逻辑消息 64 MiB，超单帧时以至多 512 KiB UTF-8 片段和递增序号双向传输，最多 256 块。握手核对能力与相同限额；分块必须保持 request_id、总字节数、序号、末块标记及重组后身份一致。完整重组前不发布结果，不接受其他消息插入未完结果。原生输入控制线程允许取消部分传输，丢弃未完成输入而不执行；错误分块使连接失效，不恢复旧协议。父进程发送队列仍限两帧，接收队列限一个完整消息；排队检查取消/截止时间，不把整个大消息的所有块放入队列。

配装请求/结果模型留在 core；应用门面向 runtime 的 search 队列提交冻结输入，Rust 负责评分矩阵、约束、六级目标、搜索及预检。原 Python solver/precheck 已删除，测试中的声明式评分矩阵也只调用隔离测试引擎，不维护 Python 备用搜索。算法/policy 标识不因模块改名变化；取消/预算不等于完成穷举。冻结方案的存储重验现也使用共享交互队列，提交的修订检查仍由存储事务执行。

配装差异通过交互队列的 `loadout_diff` 一次处理参与角色，Python 只投影明确新旧 UUID 对应的记录并恢复显示模型。Rust 每角色仅评分一次去重并集，计算保留/换入/换出、同 COST 展示配对、单件与五件评级、总分与分差；保留件数和配对分差不再由 Python 属性求值。无旧方案、旧证据不可用和新方案未配齐时保留原有状态语义，不虚构旧总分为零。`storage/plans.py` 现通过显式注入的 `AllocationService.validate` 重算评分、五件约束、换装计数、目标、评级及进度摘要，原 Python 重算循环已删除；列表只映射原生摘要。runtime、当前配装、归档、档案导入和恢复副本沿用同一依赖，不隐式创建引擎；缺少服务明确报错。验证在 SQLite 写事务开始前完成，事务内仍核对库存和配装修订，避免异步重验期间的状态变化。结构、哈希、文件锁与不可变历史仍由 Python 保存；已保存方案的单槽候选和预览已通过 replacement_candidates / replace_preview 批量提交 Rust；候选排序、五件约束、分差、评级和当前归属下的换装计数均由原生计算。预览重新核对缓存候选，不信任其 available 或分数字段；只投影明确原五件与选中 UUID，其他角色变化不阻断目标角色。子集克隆使用原生 model_objective，保留当前冻结 JSON 中 1 与 1.0 的既有口径，不改变精确目标比较；生产 Python objective/target_objective 已删除，独立小型测试 oracle 保留。筛选、实时/收录及页面残留求值仍待迁移，不宣称全业务已完成。

当前件跨模版比较使用 `current_comparison` 一次提交明确观测和冻结模版，由 Rust 计算词条贡献、当前/潜力分、评级、元数据错误降级、适配与排序。`RecommendationService` 显式注入 runtime 的共享服务，不创建独立进程所有者，不调用 Python 评分器或适配器；故障/取消/身份错误不进入缓存。记录比较按适配和分数排名；实时比较保持匹配页选择顺序，冻结快照已保证各 COST 归一化值为正，仅投影前三个存在的模版，不将该显示上限用于配装搜索。缓存跟踪词条、元数据、问题、档案、选择配置、观测 COST 确定性及资料版本，不随 UUID、装备者或截图变化重新评分。库存筛选、页面评级等仍待迁移，实际 Qt/OKWW 响应门槛仍待验证。

收录和参考评分通过 runtime 共享的 `ObservationService` 提交 `observe_stats`，Rust 返回 COST 推断/展示键、副词条最近档位、逐项贡献、当前/潜力分和冻结评级。Python 保留 OCR、坐标及文本/颜色绑定；8 项缓存仅保存数值投影，每个键最多 64 Ki 字符，较大模板不缓存，重复数值仍重建当前帧几何。手动、扫描和左右面板均显式传入服务与停止标记；扫描解析闭包的计算依赖仅捕获共享服务与事件，队列取消传到 Rust Future，正常取消不计入解析错误。原生失败清除浮层显示；引擎缺失/损坏/版本错误或重建耗尽后，当前计算所有者不再逐帧重试，新 runtime 才恢复。旧模板名称迁移、内置名称猜测评分适配和未调用的纯矩形入口已删除。方法体与独立进程测试不等于真实 OKWW 存活验收。

自定义权重由 runtime 显式持有的 `CustomWeightService` 使用 `custom_weights` 原生操作完成编辑项投影、模板构造、理想五副词条归一化与编辑证据校验。资料模块只保留字段顺序/标签；原 Python editable_values / normalize_maximum / build_custom_template / validate_edit 已删除。编辑器提交异步投影，只在 Future 已结束时取结果，并按角色、版本与取消标记丢弃迟到响应；保存只向现有权重后台线程传入系数，GUI 不调用同步构造器。`WeightProvider` 的显式计算依赖仅用于编辑保存，不让离线初始化等待引擎；后台持租约核对版本后计算，再原子发布，缺少服务或故障保留原头与快照。无效系数属于有类型业务错误，不再误杀健康通信进程；非有限 JSON 数值在输入准备阶段拒绝，避免污染共享队列。

评分测试收口时删除两项仅比较退休 scalar/prepared 后端的重复遍历，保留原有 3,876 个数值/评级黄金样例，并逐项核对原评分基线的输入、模板和期望，避免重复执行同一算法。原小数边界测试改为删除前冻结的 8 项直接期望；技能归一化和近 50 分断言继续保留，最大值输入改用删除前冻结的三组声明式数据。旧接口毒化断言仍会拦截误用，但仅在测试期间临时创建已删除属性；不将这一哨兵机制放入生产。此项删除不等于评级、库存分类、要求约束和旧格式清理全部完成。

后台库存查询由 runtime 的 `InventoryQueryService` 复用同一交互计算所有者：匹配/配装候选范围调用 `inventory_query`，库存 Reader 将复核行筛选和 saved/pending/confirmed/eligible 一并求值，原 Python filter_records / filter_review_rows / review_counts 已删除。Rust 决定可用性、等级、保护/装备者、文本匹配、时间阈值及结果行序；Python 只做输入结构检查、现有 Unicode/拼音索引准备、时间解析和原行投影。动态 tzinfo 的日历减法先由 `inventory_clock` 返回本地墙钟阈值，再由 Python 取得该瞬间的时区偏移元数据；固定偏移只需一次查询，微秒舍入保持原合同。返回 UUID/索引/统计全部校验后才发布；重复 UUID 的不同输入位置不合并，单批上限 20,000 行，超限报错不裁剪。Reader 的取消标记传到计算 Future，旧 generation 不发布；这不证明既有数据库读锁或实际 GUI 关闭等待都已整改。页面分类谓词已切换到 view 模式；业务排序、复核说明等仍有 Python 求值，继续迁移；后台查询新增的通信/准备开销也仍待优化。

库存查询输入由 `inventory_query_inputs.py` 保留完整内容身份，Rust `inventory_snapshot.rs` 保留原生行与可用性证据；两侧分别最多 2 项、按占用估算总计 8 MiB。父进程仅留内容键与快照 UUID，不持有完整协议投影，避免大库存重复占用；必要重传从当前明确输入重建。缓存不包含查询结果，条件/时间等仍每次发送。原生返回同一快照身份及保留标记，淘汰或重建后的 cache_miss 仅在原截止时间内重传一次，健康进程不因此关闭；重复身份禁止重新定义。内容/词条、kind、文本或日期准备模式变化会失效，不用物理 UUID 判断等价。主循环将输入 Value 移交计算线程，不再深复制整条消息；协议仍只有当前 v2，不增加旧输入兼容。

固定件目录使用同一 `inventory_query` 的 pins 模式，返回可用性、需纠错标记和包含“不固定”行的 COST 索引。快照一次计算验证证据，Python 只构造标签与原记录位置；全目录保留待确认/无效件，匹配页的仅可用子目录由原生按明确选项筛选，均不截断完整候选。`PlanCommands` 和匹配后台任务显式传入共享查询服务；匹配结果同时携带冻结固定件目录，通过既有 generation/修订检查后才发布。`FixedItemsPicker`、COST 代理及角色套装候选只消费目录/原生掩码，不调用 Python usable/validation_issues 或创建计算服务。角色编辑器要求已准备的目录，原 GUI 同步生成兜底与未调用的 RoleEditor 兼容对话框已删除。六个迁移前静态目录对照和相关测试验证字段、完整 10,001 件、取消/故障与行分组；方法体/静态调用核查不代替真实 Qt/OKWW 操作验收。

库存卡片筛选已切换到后台 `InventoryViewJob`：`inventory_query` 的 view 模式支持原状态组并集、COST/主词条/套装组内并集、跨组交集、副词条全包含及原检索规则，保留源行序。`ViewMetadata` 明确冻结每行的检索文本和预留标签，输入身份包含二者，不扩大各页面实际搜索字段；Unicode/完整繁简与拼音索引仍在 Python 输入边界准备，是否匹配由 Rust 求值。Qt 只映射原生索引与状态，旧 `InventoryFilters.accepts` 已从生产路径移除；取消、超时和严格关闭语义见“计算队列”与关闭路径说明，排序与真实 Qt/宿主验收仍待完成。

当前目标分政策为 `exclusive-five-target-cap-v2`（分组为 `exclusive-five-priority-target-cap-v2`）。同级组按以下字典序比较：正目标达标人数、封顶于1的最低正目标达成率、配齐人数、目标效用之和、真实总分、负换装数。目标效用为正目标角色的 `min(总分,目标)` 或零目标角色的真实总分；无正目标时最低达成率记为1。上界采用同一单调封顶函数。零目标不算达标人数，也不参与比率除法。跨优先级仍冻结前组；限时/节点结果不宣称穷举最优。

v1 求值和兼容读取已删除；不支持的政策、缺失当前计件标识或 COST 预算超过 12 时明确报错并保留原文件。当前格式历史仍使用自身冻结快照；目标分默认 0 仅作用于新角色，已有目标数值不迁移清零。

默认套装来源为XWUID公开 `resource/map/1.json` 配装样本，不从评分权重或角色属性猜测。将下载文件交给 `python tools/resources.py role-defaults --from-json PATH --retrieved YYYY-MM-DD`，再运行 `python tools/resources.py validate`；按仓库要求使用本地虚拟环境。生成器只解析声明式JSON，提取每角色五件的套装数量，保存源URL、原文件SHA256和获取日期。默认数据随包离线发布，不在设置页面联网。已保存的空配置与缺省配置必须区分。

## 页面

三页各自拥有角色配置、候选范围、草稿和结果上下文。公共shell只导航、装配页面和共享工具栏。核对与角色要求表单只有一份校验/布局；独立窗口容器复用同一页面。

异步结果携带generation、库存/资料修订和scope；旧作业完成不更新新上下文。查看历史是临时冻结投影，不覆盖工作草稿；解除保护是明确动作，移出角色不是解除保护。

## 宿主合同

当前验收依赖：Python3.12、ok-script2.0.8、PySide6 6.11.1、Fluent Widgets1.11.3。源码要求Python3.11+；未运行的组合不冒称已验证。

宿主仅扫描安装根的Python真实class：`echo_workshop_settings.py`、`echo_workshop_overlay.py`、`echo_workshop_scan.py`。它们保留原任务类名，用于旧Config身份；所有业务通过canonical `echo_workshop.*` 导入，不再fresh-exec112个helper或创建源路径hash类型注册。

内嵌页面由宿主调用 `create_import_page`；不支持该桥接的宿主可从任务卡打开同一助手窗口。安装新版本需完全重启，不承诺跨版本无重启热替换。

运行时退出先取消/停止扫描和后台作业，再关闭资料与数据库。正常取消使用统一标记，不记录为ERROR失败栈；真实错误保留阶段及堆栈。
